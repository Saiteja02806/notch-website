# How to build the Notch website

The marketing / download site is a separate Astro project that lives in
`website/` inside this repository. It is a normal Node project with its own
`package.json` and `node_modules`; the app itself never imports from it and it
never imports from the app. You can develop, build and deploy the two
independently, while keeping them in one repo.

- Site source: `website/`
- Built output: `website/dist/` (git-ignored)
- Preview server: `npm run preview`
- Local URL: `http://localhost:4321`

## 1. Prerequisites

- Node.js 20+ (tested on 24.13) and npm 11+.
- An account on **Cloudflare Pages** (free) or any static host.
- A GitHub personal access token is **not** required for local work; the CI
  refresh job uses the default `GITHUB_TOKEN`.

## 3. What the stack is

| Concern | Choice | Why |
|---|---|---|
| Framework | Astro 5.18 (static output) | No client JS by default; fast, simple |
| Styling | Tailwind v4 + a hand-written `global.css` | Tokens live once, in CSS |
| Fonts | `@fontsource-*` (self-hosted) | No third-party request, no layout shift |
| Icons | `@lucide/astro` | `lucide-astro` is deprecated |
| Sitemap | `@astrojs/sitemap` | Generated from `site` config |
| RSS | `@astrojs/rss` | `/changelog.xml` |
| Hosting | Cloudflare Pages | Free, fast, Git-driven |

Two constraints matter on this machine and are already handled:

- **Smart App Control blocks native modules.** Astro 7 pulls in `satteri`, a
  native module SAC refuses to load. Astro 5 works. Rollup's native binding is
  also blocked, so `rollup` is aliased to `@rollup/wasm-node@4.68.3` via the
  `overrides` entry in `website/package.json`. Do not remove that line.
- **`lucide-astro` is deprecated.** Use `@lucide/astro`. There is no `Github`
  icon in `@lucide/astro`; use `GitBranch`.

## 5. The four data files you edit most

- `src/data/site.ts` — brand name, repo URL, contact email, trust strip.
- `src/data/content.ts` — the tour tabs, feature splits, bento, limits, FAQ.
  Every `image` path points at a file in `public/screenshots/`.
- `src/data/changelog.ts` — curated highlights. Keep it short; full notes live
  on GitHub.
- `src/data/release.json` — **never edit by hand.** Run
  `npm run fetch:release`.
  It reads the latest GitHub release, pulls the two asset names and their
  SHA-256 from `SHA256SUMS.txt`, and sets `stableAssets` to `true` once the
  workflow publishes the version-stripped `Notch-Setup.exe` / `Notch-Portable.exe`.
  Until then the site links to the versioned asset.

## 6. Screenshots

The site uses real screenshots of the app, captured with Chrome DevTools
Protocol from a running dev instance:

1. Start the app: `npm run dev` (Electron dev server).
2. Open it with remote debugging: `node_modules\electron\dist\electron.exe . --remote-debugging-port=9232`.
3. Use the capture script in `%TEMP%\opencode\capture-shots.mjs` as a template:
   - expand the panel, switch pages via `.nav-tab`,
   - `Page.captureScreenshot` with a clip of `.panel` and `scale: 1.5`.
   - Do **not** use `Emulation.setDefaultBackgroundColorOverride` (it produces
     black images) — capture against the app's own background.
4. Save into `website/public/screenshots/`.

Use a **demo** notes folder and demo tasks for public screenshots; never ship
your real vault or real Spotify account. The state file can be backed up to
`%TEMP%\opencode\notch-state.backup.json` and restored afterwards.

## 7. Everyday development

```powershell
npm run dev          # dev server with hot reload\nnpm run build        # production build -> dist/\nnpm run preview      # serve the built output (what Cloudflare will serve)\nnpm run fetch:release # refresh release.json\n```

Edit `src/styles/global.css` for tokens, `src/components/*.astro` for sections,
`src/data/content.ts` for copy. The site has no framework components — Astro
templates plus a handful of vanilla `<script>` blocks for the tour tabs, the
copy buttons and the stage unfold.

## 8. Adding or changing a page

1. Create `src/pages/<name>.astro`, import `Base` from `@/layouts/Base.astro`.
2. Add a link in `src/components/Nav.astro` and `Footer.astro`.
3. Add the page to the sitemap automatically (it is generated from the file
   tree) — no manual list.

## 9. Deploying

The site is plain static HTML. Any host works; Cloudflare Pages is the default.

- Build command: `npm run build`
- Output directory: `website/dist`.
- Set `NODE_VERSION=20` (or 24) in the Pages environment.

### Keeping release data fresh

Add two GitHub Actions workflows under `.github/workflows/`:

- `deploy.yml` — on push to `main`, build and deploy to Cloudflare Pages.
- `refresh-release.yml` — nightly + on `release: published`, runs
  `npm run fetch:release` and commits `src/data/release.json` if it
  changed. This is what makes the download links and hashes self-updating.

The refresh script uses `GITHUB_TOKEN` for the API call; the default Actions
token is enough because releases are public.

## 10. Common errors

- **"Cannot find native binding … satteri"** — you are on Astro 7. Downgrade
  to Astro 5 (`npm install astro@5.18.2`).
- **"An Application Control policy has blocked this file … rollup"** — the
  `overrides` entry in `package.json` is missing or was removed. Re-add it.
- **"`Github` is not exported by `@lucide/astro`"** — use `GitBranch`.
- **Images are black in app screenshots** — you used
  `Emulation.setDefaultBackgroundColorOverride`. Remove it and capture against
  the app's own background.
- **`--user-data-dir` does not isolate the app** — the app reads
  `%APPDATA%\notch` regardless. Do not use it for screenshots.
- **Windows cannot disable a webcam LED while streaming** — posture shots
  will expose the room. Use the off-state screenshot and the privacy copy.

## 11. Honest-copy rules (do not break these)

- The app is **unsigned**. Every download page, the FAQ and the limits section
  must say so. Never claim "verified publisher".
- Smart App Control may block the app. Document the portable fallback and the
  system-wide trade-off.
- No auto-update exists yet. Do not promise one.
- Posture is off by default and the camera is only requested on enable.
- Notes are plain Markdown in the user's folder — no proprietary format.
- Do not re-add the removed NVIDIA AI feature without asking the maintainer.
